        Arquitectura de la solución
        
    
        
      
        
        
        Núcleo VICIdial (sin reescribir)Asterisk 20 LTS · ConfBridge en lugar de MeetMe · PJSIP en lugar de chan_sip · MixMonitor para grabaciones. Marcación, colas y telefonía quedan en el motor probado.
        
        
        ↓
        
        
        Puente APIFastAPI o Node sobre la API y la base de datos de VICIdial. Expone REST + WebSockets a la interfaz y aísla a VICIdial de internet.
        
        
        ↓
        
        
        Interfaz modernaReact + TypeScript. Pantallas por rol (agente, supervisor, admin) que se dibujan desde el perfil de operación. Es la interfaz que estás viendo en esta demo.
        
      
        
      
        
        
        CRMLeads, historial y disposiciones sincronizados en ambos sentidos a través del puente.
        
        
        Capa de IATranscripción, resumen en vivo, sentimiento, QA automático y asistente del agente sobre las grabaciones y la llamada en curso.
        
        
        DashboardsKPIs por rol y por operación, en tiempo real vía WebSockets desde el puente.
        
      
        
    
        
    
        Despliegue híbrido — la elección Azure / AWS se toma por operación
        
    
        
      
        🏢 On-premise
        
        • Asterisk + VICIdial junto a la troncal SIP: latencia mínima de voz.
        • La capa nueva corre en Docker, mismo artefacto que en cloud.
        • Ideal cuando la operación ya tiene infraestructura local.
        
      
        
      
        ☁️ Cloud · Azure o AWS
        
        • UI, puente, dashboards e IA escalan sin hardware local.
        • Conexión privada (VPN / enlace dedicado) hacia el núcleo de voz.
        • La API de VICIdial nunca se expone a internet.
        
      
        
    
        
    
        Entorno seleccionado en esta demo: On-premise. Solo cambian variables de entorno; el código es el mismo.
